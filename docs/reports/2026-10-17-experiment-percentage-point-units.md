参考 [Eurostat 百分点定义](https://ec.europa.eu/eurostat/statistics-explained/SEPDF/cache/42722.pdf)：两个百分数的差用百分点表示；绝对百分点差与相对百分比变化不同。参考 [MLflow 分开定义预期答案和评判标准](https://mlflow.org/docs/latest/genai/eval-monitor/quickstart/)，先建立独立虚构反例，再检查真实流程；不安装 MLflow，不调用云端评判，不将工程样例变成业务 gold。

固定独立工程条件：`quality_score 40% -> 44%`，绝对差 `4 个百分点`，相对差 `10%`，并覆盖下降/不变、全角百分号和非百分数单位。实际 HTTP 回放复用上一轮四个虚构 CSV、相同问题、Qwen3.5:9b / Qwen3-Embedding:4b、明确选择的运行和 OpenXML。仅做来源结构与单位表达修复，不改变指标定义、原始数值、比较计算/舍入、实验时间、检索阈值、数据集或确认条件。

## 最小改动

- 已通过可比性门的 `M#` 证据单独携带 `absolute_delta_unit`。原 `unit`、原值和差值不变；只有明确 `% / ％` 单位的差值用“个百分点”，其他单位原样保留。
- 数字事实解析把“个百分点”作为独立单位，不等同 `%`，也不再把它当成无单位数字。没有原始单位/可比性授权时，不按指标名猜测百分点。
- 问答证据、确定性回退、PPT 摘录大纲和 UI 证据卡复用同一派生单位。旧归档没有新字段时仍按保存的原单位显示，不重写旧确认计划或历史答案。
- 不接受更多近似值、不放宽事实覆盖门、不把正确单位当作正确因果。`6.17%` 的近似显示问题留待独立处理，不能借本轮绕过精确校验。
