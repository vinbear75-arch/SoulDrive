# RAG 有界回答重试的校验反馈修正

日期：2026-10-08。状态：B0 单测与真实空重试已复现；B1 与第二候选工程门、第二候选的 16 条冻结开发样本复查均通过，但 GraphRAG 内容综合目标未达。

## 真实业务现状与假设

独立审计复查 `graphrag_acceptance_isolated_audit_20261008.json` 的三个固定问题分别覆盖 hybrid/global/local。三条安全/路由验收通过，但实际终态都是 `validation_fallback`，两次回答均因缺少证据引用未被接受。前一次回放只有普通问题生成成功，另外两条仍回退，因此生成路径本身尚不稳定。

进一步检查现有回答重试，纠正指令最后一条角色为 `assistant`，而不是新的纠正请求；文本只说“校验未通过”，没有传递实际失败原因。假设仅修正反馈传递：原问题与证据保持不变，仍最多两次回答，不降低任何引用、事实、项目或研究窗口输出门。

## 外部实践

[Haystack JsonSchemaValidator](https://docs.haystack.deepset.ai/docs/jsonschemavalidator) 将实际校验错误反馈给生成器；其 [公开实现](https://github.com/deepset-ai/haystack/blob/main/haystack/components/validators/json_schema.py) 使用 `ChatMessage.from_user(recovery_prompt)`，而不是把纠正请求当作模型已说的话。

本项目只借鉴“明确角色的有界校验反馈”，不引入 Haystack 或新的自由 Agent 循环。无效模型草稿不作为新证据再次放入上下文；只传程序给出的有限校验原因，原始证据仍是唯一事实来源。

## 第二候选：在同一请求中保留原任务

[LangChain 的 RetryWithErrorOutputParser 官方说明](https://reference.langchain.com/python/langchain-classic/output_parsers/retry/RetryWithErrorOutputParser) 明确保留原提示与校验错误。只借鉴“反馈不能丢失原任务”的机制；SoulDrive 不采用其框架，也不回灌不可信的无效草稿。

第二候选修改前，新增重试保留合同 **1 failed，109 deselected，0.28 秒**：最后纠正消息中没有原问题和证据。虽然先前用户消息仍在列表内，但连续两条用户消息会让最新请求仅剩抽象校验说明；这是结构性缺口，是否导致真实失败仍须同条件验证。
