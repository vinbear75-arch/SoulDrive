日期：2026-10-08。状态：候选定向、真实开发集复查及第三轮全量检查已完成；后续 Skill 优化单独验收。

## 当前缺口和验收条件

`scripts/eval_rag.py` 的真实回答分支一直从 `rag.runtime_config.model_filename` 读取模型名；该字段是 GGUF 默认配置，不能代表已加载的 Ollama 或兼容 API 客户端。不同后端的回答因此可能全部写成同一默认 GGUF，使逐样本结果和 run manifest 的模型条件误导后续比较。

验收：优先记录已加载生成客户端的模型标识；本地 GGUF 只记录已加载文件的 basename；不知道真实客户端身份时保留未知，不能用默认值补齐。不导出凭据、端点秘密或本机模型绝对路径。

对应执行大纲 E0 的有效配置/实际模型边界，参考 [MLflow Tracking](https://mlflow.org/docs/latest/ml/tracking/) 将参数、指标和产物关联到具体运行。本项目沿用既有逐样本文件和 run manifest，不部署新的实验追踪服务。
