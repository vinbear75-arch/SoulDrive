# 记忆评测失败门与固定契约自动检查

开始日期：2026-10-07；记录更新：2026-10-08。状态：候选已通过第二轮全量工程检查。

## 目标和边界

记忆、GraphRAG 和研究窗口已有固定契约评测，但评测结果必须真的控制检查是否通过，不能只成功输出一份 JSON 就认为质量达标。本轮不调整冻结样本、标签、指标公式或及格阈值，也不将这些小样本契约门当作人工答案质量或业务泛化证明。

验收条件：记忆漏召回或禁用内容泄漏时，报告仍保留逐样本失败明细，但退出码非零；完全没有查询/上下文检查的场景必须报输入错误。既有固定数据仍通过。三个已有的离线契约评测应接入现有工程检查入口，每项失败后不得继续宣称整轮检查成功。

## 外部实践与取舍

- [Promptfoo 命令行](https://www.promptfoo.dev/docs/usage/command-line/) 将测试失败与正常成功区分为不同退出码，方便自动检查阻断。本项目复用标准进程退出码和现有评测器，不安装 Promptfoo 或调用在线裁判模型。
- [pytest 退出码](https://docs.pytest.org/en/stable/reference/exit-codes.html) 明确区分全部通过、存在失败和未收集到测试；本地评测同样不能将未执行任何质量检查解释为达标。
- [Mem0 记忆检索](https://docs.mem0.ai/core-concepts/memory-operations/search) 将范围过滤与检索元数据作为读取契约。SoulDrive 已有对应项目/工作流/时间反例；本轮修正的是这些契约失败时的工程出口，不宣称新增语义召回能力。
