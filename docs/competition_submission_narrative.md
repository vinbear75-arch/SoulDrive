# SoulDrive 参赛文稿总稿

## 1. 项目一句话定位

用户指着屏幕中的实验结果说“为什么比上个月差”，SoulDrive 在当前项目内对齐语音、授权选区、实验版本和历史偏好，在端侧给出可验证差异、原因证据等级和最小验证实验，并生成带引用的汇报草稿；歧义时先澄清，未经确认不执行外部动作。

## 2. 这个项目解决什么问题

SoulDrive 不是简单的问答壳，而是一个面向 Windows 本机的项目工作台。它要解决的是：

- 在同一项目里快速找到对的材料、对的版本、对的时间。
- 把屏幕选区、语音指令和项目知识合成一个可追溯回答。
- 把已确认结论变成报告、PPT、任务和沟通草稿。

## 3. 我们做了什么

### 3.1 项目空间与会话治理

- 项目内会话和主会话恢复逻辑已支持。
- 项目数量展示去掉了无意义的冗余数字。
- 支持项目删除、会话删除后的恢复与边界处理。

### 3.2 RAG 链路

- 项目优先检索，必要时回退到全局文档。
- 结构化来源定位可追溯到 sheet、row、line 等粒度。
- 已有跨项目私有来源隔离回归。

### 3.3 多模态链路

- 语音、屏幕选区、OCR、项目上下文和事件时间原点已贯通。
- 授权区域视觉慢路径和结构化文本快路径可区分路由。
- 多模态事件字段已进入 API 与前端事件层。

### 3.4 产物链路

- 报告、PPT、邮件和日程草案可以进入同一条证据链。
- 生成前保留确认门，不自动执行不可逆动作。

## 4. 当前已经验证的结果

- 后端关键组合测试通过。
- 前端媒体事件测试通过。
- 前端项目/文档测试通过。
- Python 编译、前端构建、Tauri `cargo check --locked` 均通过。
- 结构化检索、项目作用域检索、多模态事件透传已有回归证据。

## 5. 当前边界

以下内容不能写成“已完全完成”或“整体成绩”：

- 外部未公开评测结果。
- smoke / pilot / 合成集结果。
- 视觉慢路径完整端到端 P95 目标。
- 真实 30 条以上独立多模态业务 episode。
