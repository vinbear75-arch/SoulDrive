# SoulDrive PC B1 首轮运行报告

运行日期：2026-08-18  
运行环境：Windows 11，Conda `souldrive`，CPU 解析路径；工作区为独立的 `eval/runtime/product_b1_v0.1`。

## 1. 本轮冻结对象

本轮正式验证的是一个“端侧多模态智能体优化项目”工作空间，而不是任意文件知识库。语料包含：

- 主项目 `project_souldrive_agent`：20 个资产，含需求、技术方案、数据审计、三轮实验的报告/配置/指标/日志、会议、决策、任务、截图、图表和模板；
- 干扰项目 `project_vision_optimizer`：8 个资产，使用相似月份、实验名称和指标；
- 边界资产：2 个，分别缺少实验日期和指标定义。

资产包位于 `eval/fixtures/product_b1_v0.1`，清单为 `product_benchmark_manifest_v0.1.json`。内容是可公开的合成演示材料，不是公开训练集，也不包含个人旧文档。

### 2.4 初步产品界面

后端新增只读接口：

- `GET /projects`：本地项目列表、资产数、实验数、决策数和待办数；
- `GET /projects/{project_id}/overview`：最近实验运行、数据集版本、待办和决策摘要。

桌面端左侧新增“项目空间”区域，中央问答区显示当前项目名称；文档导入、证据检索、PPT 生成和审计入口继续复用原有工作台。接口仍受工作区挂载、口令解锁和本地 API token 保护。

### 2.5 索引与项目目录连接

当前索引 metadata schema 为 v8。若 `asset_versions.file_ref` 能精确匹配，或文件名在目录中唯一，每个切片会继承 `project_id`、`asset_id`、`asset_version_id`、`valid_from`、`authored_at` 和 `imported_at`；未登记或存在同名歧义的材料不会被猜测归属。这样项目过滤、时间语义和证据检索可以共享同一份目录事实。

## 3. 当前结论

1. 过去 36 份技术文档继续作为 B0 旧能力回归集；本轮 B1 证明了正式产品必须围绕“项目工作空间 + 实验时间线 + 版本证据”组织资料。
2. 项目目录过滤对同名实验的串项目、错时间和校正版选择有明确增益，但该结果只验证结构化检索，不代表大模型或比赛成绩。
3. 格式摄取 Candidate 已覆盖 B1 固定资产包；下一项需要单独验证的是 OCR 置信度和真实屏幕/UI 事件，而不是继续扩展文件格式。
4. `SoulDrive-PC-MMI-seed-v0.1` 已生成 30 条 schema/标签验证样本，并有 B1 规则基线；索引切片已接入项目目录元数据；仍未开始公开数据集训练、QLoRA 或 480 条业务集扩展。
5. 在业务评测集的许可证、划分、标签和评测脚本冻结前，不进行准确率提升宣称。

## 4. 下一步执行顺序

1. 在固定 B1 资产包上接入真实证据检索和“上个月实验对比”的可比性门控。
2. 对 `SoulDrive-PC-MMI-seed-v0.1` 做人工标签审阅，确认冲突、时间错位、低置信度和 OOS 标签。
3. 完成业务评测集审计后，建立 text-only baseline，再做缺失模态和多模态 Candidate。
4. 将 seed 扩展为 `SoulDrive-PC-MMI-480`，再训练 SoulAlign 和评测完整 PC Runtime。
