# SoulDrive 企业级 Agent 优化路线图

本路线图依据《深入理解 AI Agent：设计原理与工程实践》的企业级 Agent 工程主线整理，目标是把 SoulDrive 从“端侧私有知识问答系统”推进到“可评估、可审计、可控工具调用、可持续学习”的企业级 Agent harness。

## 设计假设

- SoulDrive 的核心边界仍是本地私有资产、可移动工作区、加密存储和端侧推理。
- 任何优化都必须保留当前安全边界：不默认联网、不泄露本地路径或密钥、不绕过工作区解锁。
- 优化按可验证切片推进，每个切片都需要测试、评测或审计事件证明效果。

## 1. 上下文工程

当前状态：RAG prompt 已包含文档证据、图谱上下文、长期记忆和技能计划。

优化目标：

- 引入 Agent 状态栏，稳定注入运行轨迹、检索模式、证据门控、图谱命中和学习资产状态。
- 将系统规则、状态栏、长期记忆、技能、图谱、文档证据分层组织，避免不同来源混用。
- 对文档证据使用“不可信外部摘录”边界，防止提示注入被模型当作指令执行。
- 后续引入 token-aware context packer，用 token budget 替代字符截断。

验收标准：

- prompt 单测覆盖状态栏、证据隔离和长期记忆优先级。
- 所有关键结论仍必须通过 `[E1]` 形式引用文档证据。
- 文档内“忽略规则、泄露密钥、调用工具”等文本不得改变系统行为。

## 2. Agentic RAG

当前状态：`search_with_evidence` 是一次性混合检索，然后进入答案生成。

优化目标：

- 将知识库检索封装为显式工具 `knowledge_base_search`。
- 增加轻量 ReAct 检索循环：分析问题、生成查询、观察证据、判断是否充分、必要时追加检索。
- 对多文档问题增加 final evidence selection 保护，避免重排后截断关键来源。
- 保留当前一次性 RAG 作为默认稳定路径，Agentic RAG 先通过配置或评测脚本启用。

验收标准：

- 多文档全命中率和最终证据覆盖率不低于现有基线。
- 每轮检索有 trace_id、query_variant、evidence_count、gate_decision 审计记录。
- 对证据不足问题保持拒答，不因多轮检索扩大幻觉风险。

## 3. 工具系统与权限

当前状态：工具注册表主要暴露运行态、审计和诊断工具。

优化目标：

- 工具定义包含 `access_level`、`mutates_state`、`requires_unlocked_workspace` 等元数据。
- 所有工具调用先做 schema 校验、参数边界检查和审计记录。
- 写入类或危险类工具必须显式声明权限和幂等策略。
- 面向 Agent 的工具粒度保持稳定：搜索、验证、诊断、审计、索引状态优先；文件写入和外部执行后置。

验收标准：

- 越界参数被拒绝。
- 未声明权限的状态变更工具无法注册。
- UI 和 API 返回的工具清单可以让模型区分只读、写入和危险工具。

## 4. 记忆与 Skills

当前状态：已有反思候选、人工审核、加密学习存储、skill 匹配和执行计划记录。

优化目标：

- 将 `skill_runs` 从 planned 扩展到 completed/failed 的真实闭环。
- 每次 skill 使用记录输入、产出、验证结果、失败原因和后续改进建议。
- 引入“睡眠学习”任务：在用户确认后批量归并重复记忆、沉淀稳定 SOP、淘汰低质量资产。
- 对自动生成 skill 采用评测样例和失败模式约束，避免经验污染。

验收标准：

- 学习资产更新必须可追溯到用户消息或通过审核的执行记录。
- 被拒绝或失败的 skill 不再自动注入 RAG 上下文。
- 学习评测能对比 baseline 与 runtime 的召回率、误触发率和计划可执行性。

## 5. 评估与可观测性

当前状态：已有检索、摄取、学习闭环和 harness 评测脚本。

优化目标：

- 增加 LLM-as-a-Judge 评测模式，用 rubric 对开放式回答打分。
- 建立小规模人工金标集，用于校准 judge 输出。
- 对结果比较增加显著性判断，避免根据偶然波动调参。
- 将线上运行指标与离线评测指标对齐：证据命中、拒答、引用合法率、延迟、错误类型。

验收标准：

- 每次 RAG 排序或 prompt 改动都能生成 baseline/candidate 对比报告。
- 失败样本能归因到召回、重排、证据门控、生成、引用校验或上下文压缩。
- 评测脚本输出机器可读 JSON 和人类可读摘要。

## 6. 安全与企业边界

当前状态：已有本地 API token、loopback 限制、限流、加密工作区、hash-chain 审计。

优化目标：

- 增加文档级提示注入检测与隔离提示。
- 工具调用、索引任务、解锁、导入、审计校验都写入统一 trace。
- 对导入文档记录解析器版本、索引 schema 版本、模型版本和内容哈希。
- 对敏感错误信息做脱敏，避免把本地绝对路径或密钥状态暴露给前端或模型上下文。

验收标准：

- 安全测试覆盖提示注入、越权工具、未解锁访问、远程访问、超大请求、审计链篡改。
- 任何文档内容都不能提升权限或改变工具策略。
- 恢复文档和 README 不包含本机解释器绝对路径。

## 7. 多 Agent 与异步任务

当前状态：索引 worker 已异步运行，问答仍是单 Agent 同步路径。

优化目标：

- 将长任务拆成可恢复 job：导入、索引、评测、睡眠学习。
- 多 Agent 先以角色分离实现：检索 Agent、回答 Agent、审核 Agent，不共享全部上下文。
- 通过工作区文件或数据库记录任务状态，避免进程中断后丢失轨迹。

验收标准：

- 长任务可查询、可取消、可恢复。
- 审核 Agent 只能看到交付物和证据摘要，不直接继承生成 Agent 的全部上下文。
- 并发任务不会破坏索引、学习存储和审计链一致性。

## 推荐推进顺序

1. 上下文状态栏、证据隔离、工具元数据与参数校验。
2. Final evidence selection 保护和多文档覆盖策略。
3. Agentic RAG 检索循环。
4. LLM-as-a-Judge 与显著性对比。
5. Skill run 完整闭环和睡眠学习。
6. 多 Agent 长任务编排。
