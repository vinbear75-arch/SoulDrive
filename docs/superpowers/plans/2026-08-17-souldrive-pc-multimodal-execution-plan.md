# SoulDrive PC 多模态项目知识工作台：执行方案

主设计规格：`docs/superpowers/specs/2026-08-17-souldrive-pc-multimodal-project-spec.md`

本文件只描述执行顺序、交付物和验收门禁。任何实现前先读取主规格；若两者冲突，以主规格和用户最新确认结论为准。

## 1. 已冻结的项目决策

- 产品：单用户、本机运行的多模态项目知识工作台。
- 用户：研究生、研发人员、企业知识工作者；比赛演示统一采用科研项目场景。
- 数据：用户主动导入的项目资料、过程记录、模板、结构化实验、联系人和确认产物。
- 操作：检索、组织、比较、分析、报告/PPT 生成、邮件与日程草案、确认式输出。
- 多模态：语音 + 系统选区/UI + 框选 OCR；视觉含糊时才走 VLM 慢路径。
- 隐私：默认本地；云端推理只发送用户确认的最小内容；高敏感数据可选保险箱。
- 邮件：本地联系人别名 + 本机 SMTP/API 连接器；不做员工系统、不建设 SoulDrive 云端业务服务器。
- 工程纪律：所有优化先保存对应 baseline，再实现 Candidate。

## 2. 等待赛题方回复的决策分支

收到回复后先更新主规格，不直接修改代码：

- 若认可屏幕/UI 视觉：保持当前语音 + 屏幕主链路。
- 若人体视觉为硬要求：增加有限的点头/摇头/手势通路，不做开放式情绪推断。
- 若公开集由组委会指定：以指定集为主，现有候选降为辅助。
- 若公开集由参赛者选择：审计并优先采用 MIntRec2.0，ScreenSpot 作为屏幕辅助，M3ED 仅在许可和中文实验有价值时采用。
- 若今晚仍无回复：不再阻塞工程准备，按后一条候选组合进入完整数据审计；审计不通过则替换，不盲目训练。

## 3. WP0：冻结 Harness 协议并建立 B0

### 工作

1. 盘点现有评测脚本、数据和输出格式。
2. 定义统一 `episode`、`infer request/response` 和 `run_manifest` schema。
3. 记录 Git HEAD、工作区 diff 哈希、环境、模型、配置和硬件。
4. 运行当前摄取、RAG、OCR、PPT 功能和文本 Runtime 工作负载。
5. 输出逐样本预测、指标、阶段延迟和失败分类。

### 交付物

```text
eval/schemas/episode_v0.1.schema.json
eval/schemas/run_manifest_v0.1.schema.json
eval/results/b0_current/<run_id>/run_manifest.json
eval/results/b0_current/<run_id>/predictions.jsonl
eval/results/b0_current/<run_id>/metrics.json
eval/results/b0_current/<run_id>/latency.jsonl
eval/results/b0_current/<run_id>/failures.jsonl
eval/results/b0_current/<run_id>/summary.md
```

### 验收

- 同一环境重复运行的指标和样本数一致；随机指标在预设容差内。
- B0 结果不依赖未来新代码。
- 没有 B0 不进入 WP1。

## 4. WP1：项目目录、资产版本和时间语义

### Baseline

使用当前不带项目/时间结构的混合 RAG 处理固定项目查询集，记录串项目、错时间和错版本问题。

### 工作

1. 建立 `project_catalog.sqlite` 及最小 migration。
2. 实现项目、资产、版本、实验、运行、指标、决策、任务、模板、联系人和产物实体。
3. 让现有切片和索引携带 `project_id/asset_id/version_id`。
4. 实现项目、资产类型和时间过滤后再检索。
5. 实现“上个月实验”的日期解析、候选选择、歧义澄清和可比性门控。

### 验收

- 项目间证据串用率为 0。
- 相对时间查询使用 `performed_at`，不误用 `imported_at`。
- 指标不可比时拒绝计算，不生成伪因果结论。
- 现有摄取和 RAG 指标不低于 B0 回归门槛。

## 5. WP2：屏幕选区、语音和事件 Runtime

### Baseline

- Text-only：只提供 ASR 文本。
- 规则目标：固定时间窗内选择最近显式选区。
- 规则冲突：语音实体与选区实体不一致时直接澄清。

### 工作

1. 实现按住说话、ASR 事件和置信度。
2. 实现 Windows UI Automation 选区读取。
3. 实现用户主动框选及 OCR 降级。
4. 建立带时间戳、置信度和隐私级别的事件流。
5. 实现快路径、VLM 慢路径和拒绝路径路由。

### 验收

- 用户能看见系统捕获的选区和授权截图范围。
- UIA 失败时显式降级，不后台整屏 OCR。
- 错误目标或低置信度必须澄清。
- 各阶段延迟可被 Harness 独立记录。

## 6. WP3：四条业务闭环和工作台 UI

### Baseline

- 当前一次性 RAG 回答。
- 当前 PPT 服务输出。
- 不使用画像的通用回复。

### 工作

1. 文档处理：总结、改写、待办提取、模板化整理。
2. 项目知识：证据问答、跨文档比较、实验比较。
3. 产物生成：报告计划、PPT 逐页计划、证据映射和懒加载生成。
4. 沟通与日程：草稿、目标消歧、附件与时间确认。
5. UI：项目导航、当前上下文、理解结果、证据、预览、确认和产物版本。

### 验收

- 四条路径都能从真实用户输入走到可确认产物。
- 事实回答有来源；创作内容有生成标记。
- 高风险动作无确认时不可执行。
- PPT 复用现有生成服务，不另造并行引擎。

## 7. WP4：本地联系人和邮件连接器

### Baseline

用户明确填写邮箱地址，系统只生成无个性化 `.eml` 草稿。

### 工作

1. 实现最小联系人目录：姓名、别名、邮箱、项目和称呼偏好。
2. 实现联系人歧义澄清和项目范围过滤。
3. 实现 `create_email_draft`，生成主题、正文和附件清单。
4. 实现 SMTP/API `EmailConnector` 接口；首版只接一个实际服务商。
5. 凭据接入 Windows Credential Manager。
6. 实现确认令牌、幂等键、发送审计和失败保留草稿。

### 验收

- 自动化测试只使用本地 SMTP sink/mock，不外发邮件。
- 未确认、确认后内容变化、联系人歧义或附件未确认时，发送必然失败。
- 日志、数据库和模型上下文中不出现授权码。
- 真实服务商只在用户明确授权后人工验收一次。

## 8. WP5：自建数据集与公开数据审计

### 自建集

1. 先生成 30 条种子和标注指南，验证 schema、标签互斥性和 baseline。
2. 修正设计后扩展为 480 条：320 train、80 validation、80 sealed test。
3. 按场景模板切分，禁止同模板改写跨集合泄漏。
4. 生成时间错位、ASR/OCR 错误、模态缺失、冲突、偏好和 OOS 派生样本。

### 公开集

1. 核验许可证、下载、原始模态、标签、划分、指标和官方代码。
2. 复现官方或最接近论文的 B2 Strong。
3. 建立 text-only 和缺失模态 baseline。
4. 测试集只用于冻结后的 baseline/最终 Candidate，不用于调参。

### 验收

- 数据卡、来源、哈希、许可和生成记录齐全。
- 30 条只是 schema 试验，不用于宣传模型分数。
- Sealed test 在最终评测前不可参与错误驱动优化。

## 9. WP6：SoulAlign 与主模型微调

### 工作

1. 冻结 ASR、OCR 和主 VLM，先训练 SoulAlign。
2. 训练意图、槽位、目标、对齐、冲突、澄清和 OOS 多任务头。
3. 在相同数据和预算下与 text-only、规则和 B2 Strong 比较。
4. 只有 SoulAlign 产生稳定增益后，再对主模型进行小规模 QLoRA。
5. QLoRA 只训练结构化决策到个性化回复，不让主模型绕过安全门控。

### 验收

- 完整多模态稳定超过 text-only；否则不宣称多模态创新。
- 消融能说明时序、屏幕、冲突和画像各自贡献。
- 权重、配置、种子、训练日志和环境可复现。

## 10. WP7：Runtime 性能和比赛交付

### 工作

1. 冷启动一次、热运行至少 30 次，测量各阶段 P50/P95、失败率和资源。
2. 分开报告快路径、VLM 慢路径、本地模型和云端模型。
3. 完成缺失模态、OOS、冲突、隐私出端、错误恢复和长文档压力测试。
4. 输出代码、统一推理脚本、权重/结构说明、数据卡、使用说明、可解释性和实验报告。
5. 在全新工作目录完整复现安装、导入、推理、评测和演示。

### 验收

- 完整路径满足赛题确认后的五秒口径。
- 主结果有逐样本预测、置信区间和失败分析。
- 所有竞赛主张能追溯到固定 run manifest。

## 11. 顺序约束

```text
WP0 Baseline
  -> WP1 项目数据语义
  -> WP2 多模态事件 Runtime
  -> WP3 业务/UI
  -> WP4 邮件连接器
  -> WP5 数据冻结
  -> WP6 训练与微调
  -> WP7 性能与交付
```

WP5 的公开数据审计可以与 WP1-WP4 并行准备，但任何训练必须等审计和划分冻结。摄像头、U 盘、多用户协作和更多邮箱服务商均不进入主路径。
