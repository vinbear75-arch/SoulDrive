# SoulDrive 多模态业务交互设计（第一版）

## 定位

多模态不是“把语音、截图、OCR 和视觉模型并排放在输入框旁边”，而是把用户主动提供的语音、当前屏幕选区和项目文档，组织成一个可审计的工作任务：

```text
明确任务 → 检查输入 → 授权感知 → 证据检索 → 预览产物 → 用户确认 → 生成/导出
```

系统不后台录屏、不默认采集摄像头，也不因为识别到一句话就发送邮件、写入日历或删除文件。

## 首批真实场景

| 场景 | 用户入口 | 多模态输入 | 系统路由 | 证据范围 | 产物 |
| --- | --- | --- | --- | --- | --- |
| 论文精读与组会 | 选择“论文精读 → 组会材料”，选一篇或多篇论文后说“整理这几篇论文” | 已索引论文；可选当前页/选区；可选语音要求 | 文档结构化检索；选区走 OCR 快路径，图表再走视觉慢路径 | 章节、页码、实验结果和用户授权选区 | 证据式摘要、共同主题、组会大纲，再由用户确认生成 PPT |
| 实验结果对比与问题定位 | 选择“实验对比 → 问题定位”，选两份实验报告或授权含两组数据的表格 | 两份文档，或屏幕表格；可选语音说明关注指标 | 先按项目和指标过滤，再混合检索/重排；表格低置信度时请求确认 | 同名指标、数据集/配置、表格 OCR 区域 | 差异表、已证实变化、高可信候选原因、最小验证实验 |
| 会议/阅读记录整理 | 选择“语音/阅读记录 → 行动项”，按住说话并确认转写 | 语音或已确认转写；可选会议材料/屏幕 | ASR 后提取决策和行动项，相关材料进入 RAG | 本轮确认转写、项目文档和历史会话 | 会议纪要、待办、邮件/日程草稿；外发前再次确认 |

## 交互规则

1. 任务卡先显示“缺什么”，不让用户自己猜要不要点 OCR、视觉或 RAG。
2. 屏幕采集只接受用户明确授权的窗口/选区，并显示本轮证据范围。
3. 语音转写必须允许用户确认；低置信度、时间/负责人不确定时标记“待确认”。
4. 生成 PPT、邮件和日程使用现有版本化草稿能力；确认前只生成预览，不产生外部副作用。
5. 通用问答保留为默认入口，业务任务是显式选择的增强路径；这样不会让普通问答增加无意义的感知延迟。

## 目前实现与边界

- 任务计划由本地确定性规则生成，不调用模型、不执行副作用，能明确返回输入缺口、视觉路由、证据范围和确认点。
- 任务计划会把短任务契约传给现有 RAG，回答仍必须通过现有证据引用和拒答门。
- 论文任务可直接复用现有文档选择、RAG 和 PPT 任务；会议任务可复用现有邮件/日程草稿；实验任务第一版输出分析计划，数值因果判断仍需实验数据 schema 和评测集。
- 真实的 ASR/OCR/VLM 质量与 P95 仍需在冻结的 30 条业务样本上测量，不能用“接口返回成功”代替效果结论。

## 第二版落地：视觉证据闭环（2026-08-29）

本轮按公开的一手方案校准链路：OpenAI 的 agent 设计强调把工具用途、输入、
副作用、重试安全性和错误模式写清楚，并对长上下文做有意的压缩；Claude Code
把专用子代理、细粒度工具权限和生命周期 hooks 分开；GUI-Lens 则采用
“OCR/组件粗定位 → 用户或模型选区 → 裁剪放大 → 再观察”的 coarse-to-fine
视觉定位方式。SoulDrive 只吸收适合本机单用户场景的部分，不引入云端代理或
后台录屏。

当前链路为：

```text
用户明确授权图片/窗口
  → 可选归一化框选（x/y/width/height）
  → 选区裁剪并在上限内放大
  → OCR 快路径；图表/趋势/布局等问题自动升级 VLM 慢路径
  → 记录原图范围、模型输入尺寸、路径和置信度
  → 视觉证据 V# 与文档证据 E# 分离
  → 视觉问题可由 V# 回答；项目/外部事实仍必须由 E# 支持
  → 引用校验、失败重试或明确拒答
```

这里的 `V#` 只表示“本轮截图中可见的识别结果”，不是项目文献，也不是外部
事实证明。用户换项目、换图片、换选区或改变需要 VLM 关注的问题时，旧的视觉
感知结果不会继续复用；没有明确视觉问题时，附带截图也不能绕过普通 RAG 的
证据门。

## 第三版落地：业务任务入口与语音证据（2026-08-29）

多模态入口已接入主聊天区的“业务任务”卡片。用户可显式选择论文精读、实验对比或
会议行动项；前端在发送前调用确定性计划接口，先显示缺失输入、视觉路径、证据范围和
输出契约，输入未就绪时不启动 OCR/VLM/RAG。未选择业务任务时仍走原来的通用问答。

会议任务的确认转写现在作为 `A#` 证据进入回答校验，与文档 `E#`、视觉 `V#` 分开：
没有项目文档时仍可基于本轮确认语音整理行动项，但不能把语音内容伪装成项目文献；
负责人、时间和决策不确定时必须标为待确认。邮件和日程仍只生成草稿，外发或写入前需要
已有的二次确认。

## 下一轮验收

- 每条场景各准备 10 条脱敏样本，记录 text-only、缺失模态和完整模态三组结果。
- 统计输入绑定准确率、证据覆盖率、澄清准确率、P50/P95 延迟和副作用拦截率。
- 新增视觉专项指标：选区映射准确率、V# 引用有效率、视觉问题误拒答率、无关问题绕过率和 VLM 冷/热延迟。
- 只有完整模态相对 text-only 在相同数据与配置下稳定提升，且视觉问题误拒答率和无关问题绕过率均为 0，才把多模态能力写入竞赛创新点。

## 第四版落地：目标复核与实验统计闭环（2026-08-29）

本轮吸收 [OmniParser](https://github.com/microsoft/OmniParser) 的结构化 UI
候选思路和 [GUI-Actor](https://github.com/microsoft/GUI-Actor) 的多候选加独立
验证思路，但不引入通用自动点击代理。用户勾选“目标复核”后，必须先框选授权区域，
VLM 才能以 JSON 返回多个归一化候选框；缺少框、缺少结构化候选或候选接近时，系统
只澄清，不把自由文本直接当成目标。

候选进入 SoulAlign-T 后，按时间窗口、候选置信度、UI Automation/用户框选/OCR/VLM
来源可靠度、窗口焦点和当前项目做独立融合。项目不一致会被拒绝，选中的目标仍只
是本轮对齐结果，不授予外部操作权限。相同授权截图和关注点的 VLM 结果允许在本机
有界缓存中复用，缓存命中和冷启动延迟分开记录。

“和上个月实验比较”新增本地实验台账：CSV/XLSX/JSON/YAML/日志可先生成导入确认卡，
日期、单位、数据集、split、评测脚本和配置必须明确后才写入；比较前检查项目、数据集、
脚本和指标定义，数值带源文件行或 sheet 定位；重复 run 可只读汇总均值、方差和近似
95% 置信区间。原因输出仍标记为已证实、候选或待验证，不把配置差异直接写成因果。

当前这版只证明了契约、门控和本地回归，不证明真实 VLM 目标准确率或 5 秒 P95；真实
30 条 episode、ScreenSpot 分项、热/冷延迟和同条件消融仍按路线图冻结后执行。
