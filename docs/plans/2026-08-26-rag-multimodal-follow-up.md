# RAG 与多模态后续专项计划

Skills、邮件草稿、剪贴板粘贴和项目资料管理等业务功能已完成收尾；从本计划起进入 RAG 与多模态基线阶段，任何链路优化先通过固定资料集和逐样本指标验证。

## RAG

1. 冻结一组真实项目资料和问题集，保存文档版本、项目范围、查询、期望证据和回答标签。
2. 建立 B0 baseline：当前切片、混合检索、重排、引用覆盖率、证据准确率、回答质量和延迟都记录到逐样本结果。
3. 在入库阶段增加结构感知摘要，保留父子切片、章节、页码和来源；比较摘要切片与原始切片的 Recall@K、MRR、证据覆盖和串项目率。
4. 逐项验证查询改写、多查询、重排、图谱路由和受控生成，不在没有同数据同指标 baseline 的情况下宣称提升。

## 多模态

1. 先简化界面：文本问答为默认路径，图片粘贴、截图和按住说话作为明确的可选输入，不展示内部“感知并发”等实现术语。
2. 验证本地低延迟语音链路，记录 ASR、检索、回答和人工确认的 P50/P95 延迟。
3. 对文本、图片、语音的来源、时间和置信度做对齐；出现冲突时先发澄清问题，不自动猜测或执行不可逆操作。
4. 用 text-only、缺失模态、去对齐和去冲突门控做消融，只有实际用户测试稳定改善后才保留复杂能力。

## 验收门

- 每次只改变一个核心因素，并保留配置、模型、数据版本、逐样本日志和错误样本。
- 真实资料检索准确率、图谱主题质量、持续语音体验和多模态冲突澄清，作为业务功能稳定后的专项验收指标。
